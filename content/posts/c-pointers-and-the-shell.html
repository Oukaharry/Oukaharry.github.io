I went through the ALX software engineering coursework in public. The repositories are still on my GitHub: alx-low_level_programming for C, alx-system_engineering-devops for the shell, and CPointers for the pointer exercises on their own. alx-pre_course and alx-zero_day say in their descriptions that they were my first repositories as an ALX student. None of this is a product. It is the layer under the products. I am a software developer who spends most of the time in MQL4 and Python, and both hide memory. C does not, which is why I keep the exercises next to the trading tools.

An address is not the value

The first CPointers program prints sizeof(char), sizeof(int), sizeof(float), and sizeof a local int. Those numbers depend on the machine. The next program declares int *p and prints sizeof(p). A pointer has a fixed width because it stores an address, not the object. A pointer to a char and a pointer to a large struct are the same size. The things they point at are not. Mixing the two up is how a buffer gets allocated too small.

The following program sets an int n to 98 and a pointer p to &n, then prints both addresses. They match. p does not contain 98. It contains the location where 98 is stored. The program after that writes through the pointer.

int n;
int *p;

n = 98;
p = &n;
*p = 402; /* n is now 402 */

That is the mechanism behind every later exercise that has to hand back more than one result. C can return a single value, or it can take a pointer and let the function write into the caller's variable. The same idea is in 0x05-pointers_arrays_strings in the low-level repository. reset_to_98 takes an int pointer and writes 98 through it. swap exchanges two integers by pointer, because a function that received them by value would exchange its own copies and leave the caller alone.

A C string is a pointer to the first character, with a zero byte somewhere after it. strlen walks until that byte. strcpy writes through the destination pointer. print_rev only makes sense if you can move a pointer and you also know the length. The length and the address are different facts. The header in that project, holberton.h, collects the declarations, and each .c file does one job. I still want that split when a file gets large. The trade-manager advisor is one translation unit, and placing an order, drawing a line, and closing a slice are easier to check when they are not the same function.

Arrays decay, and function pointers are addresses

An array name in an expression is the address of the first element. That is why you can pass an array to a function written for a pointer, and why sizeof on the parameter is the size of a pointer rather than the size of the array. Print the size at the call site, where the compiler still knows the array type, and pass the length yourself.

Later directories move from data pointers to function pointers (0x0F-function_pointers) and variadic functions (0x10-variadic_functions). A function pointer is the address of code. You store it, pass it, and call it. The syntax is louder than a Python callable. The idea is the same one I use when a chart level stores an action, "move the stop" or "do nothing", and another function performs it. Variadic functions, the family printf belongs to, punish a wrong format string. The CPointers programs use %p for addresses and %d for the int. A mismatch is undefined, and it will not always crash on the machine where you tried it. One of those files misspells "address" in the format string. It still compiles. The compiler is not a proofreader.

The shell is part of the language

alx-system_engineering-devops is where the C programs actually run. The published directories are shell basics, permissions, redirections, and variable expansions: print the working directory, list files, move them, and tell a file from a directory. The compiler writes a binary, the shell runs it, and the permission bits decide whether that run is allowed. Redirection keeps output you would otherwise watch scroll past. Variables stop a script from hard-coding a path.

pwd
ls -la
gcc -Wall -Wextra -pedantic 5-main.c -o deref
./deref

I still start there. Before I read a Django traceback or a MetaTrader log, I want the directory, the file I am about to run, and where the output went. The sizeof programs are short enough that -Wall would be the whole review. The devops tree stops at variable expansion. That is already enough to build and inspect the C exercises beside it.

What transferred

The coursework did not teach MQL4, MQL5, or Django. It taught a way of reading that I use in both. When a partial close mis-counts a position, I look for a value that was copied when it should have been shared, which is the swap lesson. When HedgePass Pro grows a second model with the same account fields, AccountPair and MT5Account, I look for one structure and a reference to it. When a C program and a Python program disagree about a number, I check the width of the type before the formula.

If you are starting the same projects, draw them first. Draw the box for n, the box for p, and the arrow, then write *p = 402 and update n. CPointers is that drawing. alx-low_level_programming is strings, libraries, and function pointers. alx-system_engineering-devops is the shell that runs the binary. I keep them public so the foundation sits next to the trading tools. The product work is the expert advisor and the Django app. The C is how I check my own assumptions when those programs misbehave.
